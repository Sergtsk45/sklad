Я хочу настроить систему автоматизации разработки для Claude Code CLI в этом проекте. Создай полную структуру файлов по описанию ниже. Перед созданием файлов — просканируй проект и определи стек, тестовый фреймворк, линтер, и существующие конвенции.

## Что сделать

### Шаг 1: Сканирование проекта

Определи:
- Язык и фреймворк (package.json, pyproject.toml, go.mod, Cargo.toml, pom.xml, Gemfile, composer.json)
- Тестовый фреймворк (jest, vitest, pytest, go test, cargo test, rspec, phpunit)
- Линтер (eslint, biome, ruff, pylint, golangci-lint, clippy, rubocop)
- Type checker (tsc, mypy, pyright)
- Команды из package.json scripts / Makefile / CI конфигов
- Существующие тесты: паттерн именования, расположение, моки
- Структуру документации если есть (docs/, README.md)

Покажи мне результат сканирования и жди подтверждения перед созданием файлов.

### Шаг 2: Создать CLAUDE.md в корне проекта

Файл должен содержать:

```markdown
# [Название проекта]

## Проект
[Краткое описание на основе README/package.json/pyproject.toml]
Стек: [определённый стек]

## Команды
- Запуск: [команда запуска, например npm run dev]
- Тесты (все): [npm test / pytest / go test ./... / cargo test]
- Тесты (один файл): [npx jest path/to/file / pytest path/to/file.py / go test ./pkg/...]
- Lint: [npm run lint / ruff check . / golangci-lint run]
- Lint fix: [npm run lint -- --fix / ruff check --fix]
- Type check: [npx tsc --noEmit / mypy . / pyright]
- Build: [npm run build / go build / cargo build]
- Format: [npx prettier --write . / black . / gofmt]

## Структура проекта
[Краткое описание ключевых директорий: src/, tests/, etc.]

## Стандарты кода
- Именование: [camelCase/snake_case/PascalCase — по конвенциям проекта]
- Импорты: [порядок и группировка из существующего кода]
- Обработка ошибок: [паттерн из проекта]
- Максимальная длина функции: 50 строк, метода: 30 строк
- Не оставляй console.log/print для отладки
- Используй ранний return вместо глубокой вложенности

## Тестирование
- Фреймворк: [определённый фреймворк]
- Паттерн именования: [*.test.ts / test_*.py / *_test.go — из проекта]
- Расположение: [co-located / tests/ / __tests__/]
- Моки: [jest.mock / vi.mock / pytest fixtures / testify mocks — из проекта]
- Покрытие: писать тесты на все публичные функции и edge cases
- Один assert на логическую проверку, понятные имена тестов

## Git
- Формат коммитов: conventional commits (feat:, fix:, refactor:, test:, docs:, chore:)
- Ветки: feature/*, fix/*, refactor/*
- Перед коммитом: lint + typecheck + тесты должны проходить

## Документация
- Путь: [docs/ или что есть в проекте]
- Обновлять документацию при изменении публичного API
- JSDoc/docstring для публичных функций
```

### Шаг 3: Создать slash-команды в .claude/commands/

Создай следующие файлы:

#### .claude/commands/implement.md
```markdown
Реализуй задачу: $ARGUMENTS

Шаги:
1. ПЛАНИРОВАНИЕ: Определи какие файлы нужно создать/изменить. Если задача затрагивает больше 5 файлов — сначала составь план и покажи мне.
2. КОД: Напиши код, следуя стандартам из CLAUDE.md. Используй существующие паттерны проекта.
3. ТЕСТЫ: Напиши тесты на новый код. Запусти их и убедись что проходят. Если падают — исправь (макс 3 попытки).
4. LINT: Запусти линтер и type checker. Исправь все ошибки.
5. ПРОВЕРКА: Запусти все тесты проекта чтобы убедиться что ничего не сломано.
6. ДОКУМЕНТАЦИЯ: Если изменился публичный API — обнови документацию.

Если на любом шаге что-то не получается после 3 попыток — остановись и сообщи мне.
```

#### .claude/commands/orchestrate.md
```markdown
Реализуй сложную задачу: $ARGUMENTS

## Фаза 1: Планирование
- Разбей задачу на подзадачи (максимум 7)
- Для каждой подзадачи определи: что делать, какие файлы, зависимости от других подзадач
- Покажи мне план, жди подтверждения

## Фаза 2: Выполнение
Для каждой подзадачи по порядку:
1. КОД: Реализуй подзадачу
2. ТЕСТЫ: Напиши и запусти тесты
   - Если падают → исправь (макс 3 попытки)
3. LINT + TYPECHECK: Запусти проверки, исправь ошибки
4. ИНТЕГРАЦИЯ: Запусти все тесты проекта — убедись что предыдущие подзадачи не сломаны
5. Если что-то сломалось → исправь прежде чем двигаться дальше

После каждой подзадачи кратко сообщи статус: ✅ готово / ❌ проблема.

## Фаза 3: Финализация
- Запусти полный набор тестов + lint + typecheck
- Обнови документацию если изменился публичный API
- Покажи итоговый отчёт: что сделано, какие файлы изменены, что протестировано
```

#### .claude/commands/review.md
```markdown
Проведи code review: $ARGUMENTS

Если аргумент не указан — проверь staged изменения (git diff --staged).
Если указан путь к файлу/папке — проверь эти файлы.

## Что проверять:
1. **Корректность**: баги, edge cases, race conditions, null/undefined
2. **Безопасность**: инъекции, утечки данных, хардкод секретов, небезопасные зависимости
3. **Качество**: дублирование, сложность, именование, длина функций
4. **Тесты**: покрытие новой логики, качество ассертов
5. **Стандарты**: соответствие CLAUDE.md

## Формат отчёта:
Для каждой находки:
- 🔴 CRITICAL / 🟡 WARNING / 🔵 SUGGESTION
- Файл и строка
- Описание проблемы
- Предложение исправления

После отчёта спроси: "Исправить найденные проблемы? (все / только critical / нет)"
Если да — исправь, запусти тесты, покажи diff.
```

#### .claude/commands/refactor.md
```markdown
Проведи рефакторинг: $ARGUMENTS

## Шаги:
1. АНАЛИЗ: Прочитай указанный код. Найди:
   - Длинные функции (>50 строк)
   - Дублирование
   - Глубокая вложенность (>3 уровня)
   - God objects / функции с >3 ответственностями
   - Неиспользуемый код
   - Нарушения SOLID
   Покажи находки и план рефакторинга. Жди подтверждения.

2. ТЕСТЫ ДО: Запусти существующие тесты. Если тестов нет — сообщи: "Тестов нет, рефакторинг рискован. Сначала напишем тесты? (да/нет)"
   - Если да → напиши тесты на текущее поведение, запусти, убедись что проходят
   - Если нет → продолжай с предупреждением

3. РЕФАКТОРИНГ: Применяй изменения инкрементально. Не меняй поведение — только структуру. После каждого значимого изменения — запускай тесты.

4. ПРОВЕРКА: Запусти все тесты + lint + typecheck. Всё должно проходить как до рефакторинга.

5. ОТЧЁТ: Покажи что изменилось: до/после метрики (длина функций, вложенность, дублирование).
```

#### .claude/commands/audit.md
```markdown
Проведи полный аудит проекта (или указанной области): $ARGUMENTS

## Фаза 1: Архитектура
- Структура проекта и зависимости между модулями
- Соблюдение SOLID, паттерны
- Циклические зависимости
- Разделение ответственности

## Фаза 2: Безопасность
- OWASP Top 10 применимо к стеку
- Хардкод секретов и токенов (grep -r "password\|secret\|api_key\|token" --include="*.ts" --include="*.js" --include="*.py" --include="*.env")
- SQL/NoSQL инъекции, XSS, CSRF
- Небезопасные зависимости (npm audit / pip-audit / cargo audit)
- Проверка .env, .gitignore (секреты не в репо?)

## Фаза 3: Качество кода
- Дублирование
- Сложность (функции >50 строк, вложенность >3)
- Мёртвый код
- Покрытие тестами (есть ли тесты на критические пути?)
- TODO/FIXME/HACK в коде

## Фаза 4: Отчёт
Покажи consolidated report:
- Health Score: 0-10 с обоснованием
- 🔴 Critical issues (надо исправить)
- 🟡 Warnings (желательно исправить)
- 🔵 Suggestions (можно улучшить)
- Топ-3 приоритетных действия

Спроси: "Хочешь исправить critical issues автоматически? (да/нет)"
```

#### .claude/commands/test.md
```markdown
Напиши тесты: $ARGUMENTS

Если указан файл — напиши тесты для этого файла.
Если указана функция/метод — напиши тесты для неё.
Если ничего не указано — найди непокрытые тестами файлы и предложи порядок.

## Правила:
1. Изучи существующие тесты в проекте — следуй тем же конвенциям (фреймворк, стиль, именование, моки)
2. Тестируй:
   - Happy path
   - Edge cases (пустые значения, граничные условия, null/undefined)
   - Ошибки (невалидный ввод, сетевые ошибки, таймауты)
3. Каждый тест — один логический assert, понятное имя
4. Моки — только для внешних зависимостей (API, DB, файловая система)
5. Запусти написанные тесты, убедись что все проходят
6. Если тест падает из-за бага в коде — сообщи, не маскируй фикстурами
```

### Шаг 4: Создать .claude/settings.json

```json
{
  "permissions": {
    "allow": [
      "Bash(npm test*)",
      "Bash(npx jest*)",
      "Bash(npx tsc*)",
      "Bash(npm run lint*)",
      "Bash(npm run build*)",
      "Bash(npx prettier*)",
      "Bash(git diff*)",
      "Bash(git log*)",
      "Bash(git status*)"
    ]
  }
}
```

ВАЖНО: Замени команды в permissions.allow на реальные команды этого проекта (если Python — pytest, ruff; если Go — go test, golangci-lint; и т.д.). Разрешай только безопасные read-only и тестовые команды.
