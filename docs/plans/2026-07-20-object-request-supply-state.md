# План: корректное обеспечение строк требования на комплектацию

**Дата:** 2026-07-20  
**Статус:** Завершена и задеплоена на prod
**Модуль:** `object_request`

## Цель

Сделать состояние строк требования достоверным для двух источников
обеспечения:

1. складская выдача через `stock.picking`;
2. закупка с поступлением непосредственно на склад объекта.

После подтверждения любого фактического движения Odoo должна пересчитывать
фактически обеспеченное количество, оставшуюся потребность, плановые поля
`К выдаче` / `К закупке` и пользовательский статус строки.

## Принятые правила

- Поступление по связанному `purchase.order.line` на склад объекта считается
  обеспечением требования, как и выдача с внутреннего склада.
- `qty_issued` остаётся общим фактически обеспеченным количеством для
  совместимости с текущими отчётами и данными; в пользовательском интерфейсе
  его подпись будет уточнена до «Обеспечено».
- `qty_to_issue` и `qty_to_buy` — только план оставшейся потребности, а не
  подтверждённые количества.
- Статус `fully_supplied` возможен только при
  `qty_issued >= qty_requested`, независимо от источника обеспечения.
- При `0 < qty_issued < qty_requested` статус — `partially_issued`; при
  отсутствии фактического обеспечения строка остаётся `ready`.
- Нельзя автоматически заново включать в закупку или выдачу уже
  обеспеченное количество.

## Критерии приёмки

1. После полного поступления закупочной строки прямо на склад объекта её
   `К закупке` равно `0`, а строка имеет статус «Полностью обеспечено».
2. Частично поступившая закупка показывает только неполученный остаток
   «К закупке» и статус «Частично обеспечено».
3. Строка с комбинацией выдачи и закупки закрывается только после
   обеспечения всего `qty_requested`.
4. Повторный запуск синхронизации не удваивает `qty_issued`.
5. Незавершённые документы не учитываются как фактическое обеспечение.
