# План: объединение вкладок «Строки» и «Обработка» в форме требования

**Дата:** 2026-07-27  
**Статус:** Завершена и задеплоена на prod 2026-07-27 (`19.0.1.10.2`)  
**Модуль:** `object_request`

## Цель

Упростить форму `object.request`: убрать отдельную вкладку **«Обработка»**, перенести
нужные элементы на вкладку **«Строки»** и в шапку документа, чтобы снабженец работал
с таблицей строк и действиями обработки в одном месте.

## Текущее состояние (форма `object_request_views.xml`)

| Элемент | Где сейчас |
|---|---|
| «Основные данные», «Ответственные» | Шапка над notebook |
| Вкладка **«Строки»** (`page_lines`) | Кнопки «Отсортировать строки», «Проверить номенклатуру»; таблицы `line_ids` (прораб / снабжение) |
| Вкладка **«Обработка»** (`page_processing`) | «Сводка по количествам», «Статистика строк», «Статус сопоставления», кнопки «Рассчитать наличие», «Авто-разбивка», «Подготовить закупку» |
| Другие вкладки | «Сопоставление», «Размещение по складам», «Связанные документы», «Импорт» — **не трогаем** в этой задаче |

## Принятые решения

1. Вкладку **«Обработка»** удалить полностью (`page_processing`).
2. Блок **«Сводка по количествам»** (`qty_total_*`) в UI **не показывать**  
   (поля модели и отчёты не удалять).
3. Блок **«Статистика строк»** (`line_count`, `line_matched_count`, …) перенести в шапку:
   третья колонка `group` в одной строке с **«Основные данные»** и **«Ответственные»**.
4. Поле **«Статус сопоставления»** (`matching_state`) включить в блок статистики в шапке
   (readonly, как сейчас).
5. Кнопки обработки объединить с кнопками вкладки «Строки» в **одну строку** (один `div`):
   - «Отсортировать строки»
   - «Проверить номенклатуру»
   - «Рассчитать наличие»
   - «Авто-разбивка»
   - «Подготовить закупку»
6. Сохранить существующие `groups`, `invisible`, `title`, `confirm` и классы кнопок;
   для трёх кнопок обработки — `invisible="state not in ('draft', 'in_progress')"` как на вкладке «Обработка».
7. Права: toolbar строк — `object_request.group_supply_manager` (как сейчас для кнопок снабжения).

## Результат

- Вкладка `page_processing` удалена из формы.
- Статистика строк и `matching_state` перенесены в шапку документа.
- Пять рабочих кнопок объединены на вкладке `page_lines`.
- Добавлен регрессионный тест структуры формы в `test_obr009_mass_actions.py`.
- Модуль поднят до `19.0.1.10.2`.
- Ручная проверка ролей в браузере остаётся отдельным шагом перед deploy.

## Вне scope

- Перенос вкладок «Сопоставление» и «Размещение по складам».
- Удаление computed-полей `qty_total_*` из модели.
- Изменение логики `action_check_stock`, `action_auto_split`, `action_open_purchase_wizard`.

## Критерии приёмки

1. На форме требования нет вкладки «Обработка».
2. На вкладке «Строки» в одной строке доступны все пять кнопок (для снабженца, с прежними условиями видимости).
3. В шапке рядом с «Основные данные» и «Ответственные» отображается статистика строк и статус сопоставления.
4. Блок «Сводка по количествам» нигде на форме не показывается.
5. Существующие Odoo-тесты модуля `object_request` проходят; добавлен/обновлён тест на наличие кнопок в `page_lines`.
