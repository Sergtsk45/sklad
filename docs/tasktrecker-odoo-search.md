# Tasktracker: custom_product_search

## Задача: Улучшенный поиск товаров в Odoo 19
- **Статус**: Завершена
- **Дата старта**: 2026-05-06
- **Описание**: Реализовать отдельный addon `custom_product_search`, который улучшает поиск товаров в backend UI, складских документах и сервисном слое AI-ассистента за счет нормализации товарных названий, поиска по SKU/barcode/name и PostgreSQL trigram-индексов.
- **Ограничения**:
 - Не изменять ядро Odoo.
 - Не нарушать ACL/security Odoo: поиск и AI-сервис работают через стандартные `search/search_fetch/read`, без повышения прав для домена поиска.
 - Addon должен работать без OCA `base_search_fuzzy`; если модуль установлен, реализация должна быть совместимой и не конфликтовать.
 - Не использовать хардкод складов; `warehouse_id` передается параметром и применяется через стандартный context.

## Архитектурные решения
- **API поиска Odoo 19**: в текущем исходном коде Odoo 19 `product.product` переопределяет `name_search(name='', domain=None, operator='ilike', limit=100)`, а базовый `odoo.orm.models.Model.name_search` выполняет поиск по `display_name`. Поэтому расширение backend Many2one поиска будет сделано через `name_search()` с актуальной сигнатурой Odoo 19, а не через неиспользуемый legacy `_name_search()`.
- **Нормализация**: общий helper `normalize_product_search_text()` в addon используется и compute-полями, и поисковым сервисом.
- **Поиск по словам**: для запросов вида `кран ду50` применяется AND-поиск по токенам нормализованного запроса внутри `x_search_name`, потому что простой `ilike` по полной строке не найдет `кран шаровый ду50`.
- **Индексы**: `index=True` на полях остается для стандартного B-tree индекса, а `post_init_hook` дополнительно создает `pg_trgm` GIN индексы для ускорения `ilike`.

## Критерии приемки
- Запросы `кран шаровый Ду50`, `кран ду50`, `шаровый ду 50`, `ДУ50` находят товар `кран  шаровый  Ду50`.
- Поиск учитывает `default_code`, `barcode`, `name`, `x_search_name`, `product_tmpl_id.x_search_name`.
- AI-метод возвращает результаты с учетом прав текущего пользователя и опционального складского контекста.
- Addon устанавливается отдельно и не меняет core Odoo.
- README содержит понятные ручные сценарии проверки.
