# Tasktracker: Wizard V2 — импорт Excel с гибким форматом колонок

**Создано:** 2026-06-10  
**Статус:** Выполнено  
**Модуль:** `custom_addons/object_request`  
**Основной объект:** `object.request.import.wizard`

## Контекст

Текущий wizard импорта Excel для требований на комплектацию ожидает фиксированный порядок колонок:

| № | Артикул | Наименование | Ед. | Кол-во |

Файл `docs/УУТЭ ул. Б. Хмельницкая_112 шифр 37-000_09-2025.xlsx` использует близкий, но другой формат:

| № | Наименование | Обозначение | Единица измерения | Количество |

Из-за жёсткого чтения колонок по индексам прямой импорт перепутает данные:

- `Наименование` попадёт в поле `supplier_article`.
- `Обозначение` попадёт в поле `name_raw`.
- Остальные поля будут прочитаны корректно только случайно, если позиции совпадают.

## Решение

Отдельный wizard не нужен. Нужно доработать существующий `object.request.import.wizard`, чтобы он определял назначение колонок по заголовкам и поддерживал несколько синонимов для одного поля.

Цель — сохранить один пользовательский сценарий импорта, но сделать парсер устойчивым к двум поддерживаемым форматам:

- текущий формат wizard: `№`, `Артикул`, `Наименование`, `Ед.`, `Кол-во`;
- формат спецификации УУТЭ: `№`, `Наименование`, `Обозначение`, `Единица измерения`, `Количество`.

## Критерии готовности

- Wizard корректно импортирует старый формат `№ / Артикул / Наименование / Ед. / Кол-во`.
- Wizard корректно импортирует формат `№ / Наименование / Обозначение / Единица измерения / Количество`.
- В preview `Кран муфтовый...` отображается как наименование, а `11Б27п1` как артикул/обозначение.
- Ошибки неподдерживаемого Excel объясняют, каких колонок не хватает.
- Существующие сценарии `object.request.import.wizard` не ломаются.
- Тесты изменённого модуля проходят.
- `docs/changelog.md` обновлён после реализации.

## Риски и контроль

- **Риск:** разные поставщики могут использовать похожие, но неучтённые названия колонок.  
  **Контроль:** нормализовать заголовки и держать словарь синонимов расширяемым.

- **Риск:** файл может содержать служебные строки до заголовка.  
  **Контроль:** на первом этапе поддержать заголовок в первой строке; поиск заголовка по первым N строкам вынести в отдельную следующую задачу, если появятся такие файлы.

- **Риск:** `Обозначение` не всегда является артикулом поставщика.  
  **Контроль:** использовать его как `supplier_article` только в контексте Excel-импорта, не менять модель данных.
