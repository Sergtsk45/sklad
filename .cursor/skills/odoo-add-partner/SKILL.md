# Odoo: Добавление контрагента

## Главные правила

- Изменяй данные в Odoo только по явной команде пользователя: «создай», «внеси», «добавь», «обнови».
- Если пользователь спрашивает «можешь ли ты?» или «как лучше?» — только объясни, ничего не создавай.
- Перед созданием всегда ищи дубликат по ИНН (`vat`).
- Если ИНН отсутствует или сомнителен — остановись и попроси уточнить ИНН.
- Не затирай заполненные поля существующего контрагента без отдельного подтверждения.

## Шаг 1 — Уточнить категорию

Перед записью в Odoo убедись, что понятна категория контрагента. Если пользователь не указал категорию явно, спроси, к какой категории отнести контрагента:

- `Поставщик`
- `Заказчик`
- `Покупатель`
- `Подрядчик`

Используй выбранную категорию как тег `res.partner.category`. Если тега нет — создай его.

### Связь категории с рангами

| Категория | Поля Odoo |
|-----------|-----------|
| `Поставщик` | `supplier_rank = 1`, `customer_rank = 0` |
| `Заказчик` | `customer_rank = 1`, `supplier_rank = 0` |
| `Покупатель` | `customer_rank = 1`, `supplier_rank = 0` |
| `Подрядчик` | `supplier_rank = 1`, `customer_rank = 0` |

Если пользователь просит несколько ролей, установи оба ранга в `1` и добавь все соответствующие теги.

Ранги из таблицы применяй только при **создании**. При **обновлении** существующего контрагента ранги только повышай (`0 → 1`) — никогда не обнуляй уже установленный ранг другой роли.

## Шаг 2 — Нормализовать входные данные

Собери поля для `res.partner`:

| Поле Odoo | Что заносить |
|-----------|--------------|
| `name` | Полное юридическое наименование |
| `ref` | Сокращенное наименование, если есть |
| `vat` | ИНН: 10 цифр для юрлица, 12 цифр для ИП/физлица |
| `is_company` | `true` для юрлиц и госорганов; `false` для физлиц |
| `country_id` | Россия, если адрес в РФ |
| `state_id` | Регион, если однозначно определяется |
| `zip` | Индекс |
| `city` | Населенный пункт |
| `street` | Улица, дом, офис |
| `phone` | Общие телефоны организации |
| `email` | Общий email организации |
| `comment` | КПП, ОГРН, ОКПО, ОКТМО, ОКВЭД, ОКОГУ, ОКОПФ, л/с, руководитель, примечания |

### Уточнения из практики

- Госорганы и учреждения считай компаниями: `is_company = true`.
- КПП не храни в `vat`; `vat` содержит только ИНН.
- Если телефон указан как `(84162)` для Благовещенска, возможно это ошибка; стандартный код города — `+7 (4162)`. Исправляй только когда регион и номер очевидны, иначе уточняй.
- Исправляй явные опечатки в ФИО только если они очевидны: например `Нталья` → `Наталья`. В ответе обязательно отметь такое исправление.
- Единый казначейский счет, лицевой счет и дату действия банковских реквизитов сохраняй в `comment`, если нет специальных полей.

## Шаг 3 — Проверить дубликат

Всегда выполни поиск:

```text
search_records(
  model="res.partner",
  domain=[["vat", "=", "<ИНН>"]],
  fields=["id", "name", "vat", "display_name", "customer_rank", "supplier_rank", "phone", "email"]
)
```

Если найден контрагент с тем же ИНН:

- сообщи пользователю о совпадении, если название заметно отличается;
- обновляй только пустые поля; заполненные поля не перезаписывай — перечисли их пользователю как пропущенные;
- добавь недостающий тег категории, не удаляя существующие теги;
- подними `customer_rank` / `supplier_rank` с 0 до 1, если новая роль еще не отмечена;
- никогда не меняй `vat` существующей записи — при расхождении ИНН остановись и уточни у пользователя.

Если пользователь просит дополнить данные контрагента без ИНН (по названию) — найди запись через поиск по имени; при нескольких совпадениях покажи кандидатов и попроси выбрать.

## Шаг 4 — Подготовить тег категории

Проверь тег:

```text
search_records(
  model="res.partner.category",
  domain=[["name", "ilike", "<Категория>"]],
  fields=["id", "name"]
)
```

Если точного тега нет:

```text
create_record(
  model="res.partner.category",
  values={"name": "<Категория>"}
)
```

В `res.partner.category` используй точное имя категории из разрешенного списка.

## Шаг 5 — Создать или обновить контрагента

### Создание

```text
create_record(
  model="res.partner",
  values={
    "name": "...",
    "ref": "...",
    "is_company": true,
    "vat": "...",
    "country_id": <id>,
    "state_id": <id>,
    "zip": "...",
    "city": "...",
    "street": "...",
    "phone": "...",
    "email": "...",
    "customer_rank": 1,
    "supplier_rank": 0,
    "category_id": [[6, 0, [<tag_id>]]],
    "comment": "КПП: ...\nОГРН: ..."
  }
)
```

### Обновление

```text
update_record(
  model="res.partner",
  record_id=<id>,
  values={
    "category_id": [[6, 0, [<existing_tag_ids>, <new_tag_id>]]],
    "customer_rank": 1
  }
)
```

Для существующего контрагента не используй `[[6, 0, ...]]`, пока не получил текущие `category_id`: иначе можно стереть старые теги.

## Шаг 6 — Банковские реквизиты

Если пользователь дал банковские реквизиты:

1. Найди банк по БИК в `res.bank`.
2. Если банка нет — создай `res.bank` с `name`, `bic`, `country`.
3. Создай банковский счет в `bank_ids` или `res.partner.bank`.

Основной расчетный счет сохраняй как `acc_number`. Казначейский счет, корреспондентский счет, лицевой счет и дату действия реквизитов добавляй в `comment`, если стандартная модель не дает отдельного надежного поля.

## Шаг 7 — Контактные лица

Контакты сотрудников создавай как дочерние `res.partner`:

```text
"child_ids": [[0, 0, {
  "name": "ФИО",
  "type": "contact",
  "function": "Роль",
  "phone": "+7...",
  "email": "..."
}]]
```

Если в тексте указаны «по закупкам», «ответственный завхоз», «руководитель» — заноси их как контактные лица, кроме руководителя без телефона/email: его можно оставить в `comment`.

## Шаг 8 — Проверка результата

После создания/обновления получи карточку через `get_record` и проверь:

- `name`, `ref`, `vat`;
- адрес, телефон, email;
- `customer_rank` / `supplier_rank`;
- `category_id`;
- `bank_ids`;
- `child_ids`.

## Ответ пользователю

Сообщи кратко:

- создан или обновлен контрагент;
- ID и ссылка на карточку;
- какая категория/тег применены;
- какие банковские реквизиты и контактные лица добавлены;
- какие данные были нормализованы или исправлены;
- какие поля сохранены в примечании из-за отсутствия отдельного стандартного поля.

Не выводи секреты или токены. Банковские реквизиты контрагента можно перечислять, если пользователь сам их предоставил.

## Синхронизация с ai_assistant

Этот скилл — канонический workflow работы с контрагентами. Те же правила воспроизводятся
во встроенном Odoo-ассистенте (`custom_addons/ai_assistant`, блок правил контрагентов в
`services/prompt_builder.py` и tools `create_partner_draft` / `update_partner_draft`).
При изменении правил в этом скилле обнови и правила/tools в `ai_assistant`
(трекер доработки: `docs/tasktrecker-creat-partner-v2.md`).
