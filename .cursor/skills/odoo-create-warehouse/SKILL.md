# Odoo: создание склада

Переносимый workflow для складского агента. Работает в любом проекте с Odoo
Inventory и MCP (`search_records`, `create_record`, `get_record`,
`update_record`). Не хардкодь company id, URL, имена серверов MCP и коды
складов текущего инстанса.

Примеры вызовов — [examples.md](examples.md).

## Главные правила

- Меняй данные **только** по явной команде: «создай», «добавь», «заведи»,
  «сделай полки». Вопрос «можешь ли?» — только объяснение, без MCP create.
- Не удаляй склады и локации. Не переноси остатки «заодно».
- Не передавай при создании `lot_stock_id`, `view_location_id`, типы операций
  и маршруты: Odoo создаёт их сам.
- `stock.warehouse` обычно **без chatter** (`mail.thread`) — не вызывай
  `post_message`.
- Имя MCP-сервера разное в проектах: найди сервер Odoo через каталог MCP,
  не предполагай `user-odoo`.

## Что нужно от пользователя

Минимум: **название склада**.

| Данных нет | Действие |
|------------|----------|
| Название | Остановись, спроси |
| Короткий код | Сгенерируй (см. ниже), покажи в отчёте |
| Компания / адрес | Возьми с похожего склада той же базы |
| Полки | Создавай **только если названы** |
| Пополнение с другого склада | Только если пользователь сказал |
| Приёмка сразу на полку | Только если явно просил правила размещения |

## Чеклист

```
- [ ] Явная команда
- [ ] Поиск дубля по name и code
- [ ] Образец настроек с похожего склада
- [ ] Уникальный короткий code
- [ ] create stock.warehouse
- [ ] Проверка локаций и типов операций
- [ ] Полки (если просили)
- [ ] resupply / putaway (если просили)
- [ ] Отчёт пользователю
```

## Шаг 1 — Найти MCP и образец

1. Найди MCP-сервер Odoo (имя содержит `odoo`).
2. Сними схему `create_record` / `search_records` / `get_record`.
3. Загрузи существующие склады:

```text
search_records(
  model="stock.warehouse",
  domain=[],
  fields=["id", "name", "code", "company_id", "partner_id",
          "lot_stock_id", "in_type_id", "reception_steps",
          "delivery_steps", "buy_to_resupply"],
  order="id asc"
)
```

4. Возьми образец: склад того же типа (контейнер, объект, расходники) или
   первый активный склад компании. С него копируй `company_id`, `partner_id`,
   `reception_steps`, `delivery_steps`, `buy_to_resupply`, если пользователь
   не задал иное.

Типичный дефолт, если складов ещё нет: `reception_steps="one_step"`,
`delivery_steps="ship_only"`, `buy_to_resupply=true`.

## Шаг 2 — Дубликат

Ищи по имени **и** коду (включая сгенерированный):

```text
search_records(
  model="stock.warehouse",
  domain=["|", ["name", "ilike", "<название>"], ["code", "=", "<код>"]],
  fields=["id", "name", "code", "lot_stock_id", "in_type_id"]
)
```

Если найден тот же склад — **не создавай второй**. Сообщи ссылку. Если просили
полки — переходи к шагу 5 на существующем `lot_stock_id`.

## Шаг 3 — Короткий код (`code`)

`code` обязателен и должен быть уникален. На многих версиях Odoo длина
**не больше 5 символов** (включая кириллицу). Если create падает на длине —
укороти и повтори.

Приоритет:

1. Код, который дал пользователь (если уникален и проходит ограничение).
2. Иначе сожми название: аббревиатура + номер из имени.

| Название | Код |
|----------|-----|
| Контейнер_5 | `Кнт5` |
| Расходники | `Расх` |
| Основной склад | `Ос.ск` |
| Объект O018 | `O018` |

Латиница не обязательна: кириллический код допустим, если так принято в базе.
Перед create ещё раз проверь уникальность кода.

## Шаг 4 — Создать склад

```text
create_record(
  model="stock.warehouse",
  values={
    "name": "<название>",
    "code": "<код>",
    "company_id": <id из образца>,
    "partner_id": <id из образца или адрес пользователя>,
    "buy_to_resupply": true,
    "reception_steps": "one_step",
    "delivery_steps": "ship_only"
  }
)
```

Сразу проверь:

```text
get_record(
  model="stock.warehouse",
  record_id=<id>,
  fields=["name", "code", "company_id", "lot_stock_id",
          "view_location_id", "in_type_id", "out_type_id",
          "int_type_id", "reception_steps", "delivery_steps",
          "buy_to_resupply"]
)
```

Ожидаемо после create:

- `view_location_id` — view-локация с именем = `code`;
- `lot_stock_id` — внутренняя локация запаса (`Наличие` / `Stock` / `Полки`
  — как в языке базы);
- типы: Поступления / Incoming, исходящие, внутренние.

Не удаляй служебные Input/Output/Pack/QC, даже если шаги приёмки = 1.

## Шаг 5 — Полки

Только если пользователь перечислил полки/ячейки.

Родитель: `lot_stock_id` склада (не view-локация).

Перед create проверь, что такого имени ещё нет среди детей:

```text
search_records(
  model="stock.location",
  domain=[["location_id", "=", <lot_stock_id>]],
  fields=["id", "name", "complete_name", "usage"]
)
```

Создавай каждую полку **как сказал пользователь** (не переименовывай
`Н1` → «Полка Н1», если не просили):

```text
create_record(
  model="stock.location",
  values={
    "name": "<Н1>",
    "usage": "internal",
    "location_id": <lot_stock_id>,
    "company_id": <company_id склада>
  }
)
```

После пакета — повторный search детей, сверка списка.

Приёмка по умолчанию остаётся на `lot_stock_id`. Правила putaway или
`default_location_dest_id` у `stock.picking.type` меняй **только** если
пользователь явно хочет «класть сразу на полку X».

## Шаг 6 — Пополнение с другого склада

Только по явной просьбе:

```text
update_record(
  model="stock.warehouse",
  record_id=<id>,
  values={"resupply_wh_ids": [[6, 0, [<id_склада_источника>]]]}
)
```

Сначала прочитай текущие `resupply_wh_ids`, чтобы не стереть уже заданные.

## Ответ пользователю

Кратко:

- создан новый склад или найден дубль;
- id, `code`, ссылка из MCP если есть;
- локация запаса и тип поступления (`in_type_id`);
- список полок с полными путями (`Кнт5/Наличие/Н1`);
- что не делалось (putaway, resupply), если это логично предложить следующим
  шагом.

## Чего не делать

- Не создавать второй склад с тем же именем «на всякий случай».
- Не делать полки на view-локации склада.
- Не ставить `usage` полок в `view` — только `internal`.
- Не менять `lot_stock_id` склада на одну из полок без отдельной команды.
- Не настраивать putaway «для красоты».
- Не коммитить `.env` и URL с секретами в скилл.
