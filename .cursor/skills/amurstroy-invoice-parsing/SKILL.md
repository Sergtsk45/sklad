# Парсинг договор-счетов ОАО УПТК «Амурстрой»

## Когда применять

1. PDF **без текстового слоя** (`len(page.chars) == 0`).
2. В OCR-тексте есть **ИНН `2801019127`** или **«Амурстрой»** + **«Договор-Счет»**.
3. Имя файла вроде `schetП000014101.pdf`, `Родбант.pdf`, `ручка дверная schet…`.

Если формат не Амурстрой — скилл **scanned-invoice-parsing**.

**Не заносить в Odoo** без явной команды (`agent-intent-odoo-mcp`).

---

## Шаг 1 — Запуск парсера

```bash
python3 .cursor/skills/amurstroy-invoice-parsing/scripts/amurstroy_parse.py "docs/invoices/<файл>.pdf"
python3 .cursor/skills/amurstroy-invoice-parsing/scripts/amurstroy_parse.py "docs/invoices/<файл>.pdf" --json
```

Общий OCR (`ocr_parse.py`) **автоматически** вызывает парсер Амурстроя при распознавании поставщика.

## Шаг 2 — Формат документа

| Поле | Значение |
|------|----------|
| Тип | Договор-счёт |
| Номер | `П000014101` (OCR может дать `14101` → нормализуется) |
| `partner_ref` | Полный номер с префиксом `П` |
| Поставщик | ОАО УПТК «Амурстрой», ИНН `2801019127`, КПП `280101001` |
| Покупатель | ООО «Теплосервис-Комплект», ИНН `2801131520` |
| Скидка | Обычно **5%** на все строки |
| Итого для PO | Строка **«на сумму … руб»** (без НДС), не «Итого:» с НДС |

Подробности колонок — [amurstroy-table-format.md](amurstroy-table-format.md).

## Шаг 3 — Структура JSON

```json
{
  "format": "amurstroy_contract_invoice",
  "partner_ref": "П000014101",
  "needs_review": true,
  "invoice_number": "14101",
  "supplier": { "inn": "2801019127", "name": "..." },
  "items": [
    {
      "name": "Клей Момент \"88\", 750мл",
      "qty": 10,
      "unit": "шт",
      "price": 1657.0,
      "amount": 15741.5,
      "discount_percent": 5.0
    }
  ],
  "totals": {
    "subtotal_wo_vat": 21553.6,
    "total": 21973.6,
    "vat": 3006.71,
    "items_sum": 21544.1
  },
  "warnings": ["sum_mismatch: ..."]
}
```

Для `purchase.order` использовать:
- `price_unit` = `price`
- `product_qty` = `qty`
- `discount` = `discount_percent`

---

## Шаг 4 — Валидация

```
✓ Σ items[].amount ≈ totals.subtotal_wo_vat (допуск 1 ₽)
✓ discount_percent ≈ 5% (или восстановлен из сумм)
✓ partner_ref начинается с «П»
✓ Рекламные блоки («В продаже имеются…») не в items
```

При `sum_mismatch` в `warnings`:
1. Покажи пользователю расхождение.
2. Не додумывай позиции — попроси уточнить или пересканируй.
3. Допустима ручная правка **только** с явного согласия.

`needs_review: true` — машинный стоп-флаг. При нём нельзя создавать `purchase.order`
автоматически, даже если пользователь ранее просил пакетную обработку. Сначала покажи
расхождение и получи подтверждение по конкретному счёту.

## Шаг 5 — Известные проблемы OCR

| Симптом | Причина | Действие |
|---------|---------|----------|
| `items` пустой | Старый общий парсер | Использовать **amurstroy_parse.py** |
| Сумма строк ≠ итог | Склеенные цифры, потеря строк | См. `warnings`, сверка с PDF |
| `50 м` в названии ленты | Размер в мм, не единица заказа | Парсер игнорирует «м» в названии |
| `(36 308.00` | Номер строки + цена | Постобработка в парсере |
| `10 389.00` вместо `4389.00` | Разорванная сумма | Восстановление по gross×0.95 |

Словарь исправлений: [ocr-corrections.md](../scanned-invoice-parsing/ocr-corrections.md) + [amurstroy-table-format.md](amurstroy-table-format.md).
