# Закупка из счёта поставщика

## Предусловия

- Пользователь **явно** поручил создать закупку (правило `agent-intent-odoo-mcp`).
- Счёт распознан (скилл `scanned-invoice-parsing` или текстовый PDF).
- Известны: номер счёта, дата, поставщик (ИНН), таблица позиций, итого.
- Если парсер вернул `needs_review: true`, `items_empty` или `sum_mismatch` — **не создавать PO** без отдельного подтверждения пользователя после показа расхождения.

---

## Шаг 1 — Проверить дубликат закупки

```
search_records(
  model="purchase.order",
  domain=[["partner_ref", "=", "<номер_счёта>"]],
  fields=["id", "name", "state", "amount_total", "picking_type_id"]
)
```

Если найден — сообщи пользователю ссылку, **не создавай** второй PO на тот же счёт.

---

## Шаг 2 — Поставщик

```
search_records(model="res.partner", domain=[["vat", "=", "<ИНН>"]], ...)
```

Нет записи → скилл `odoo-supplier-from-invoice` (создать/обновить, `supplier_rank: 1`).

---

## Шаг 3 — Склад приёмки

```
search_records(
  model="stock.warehouse",
  domain=[["name", "ilike", "<название склада>"]],
  fields=["id", "name", "in_type_id"]
)
```

В `purchase.order` передать `picking_type_id` = `in_type_id` склада.

Опционально: локация-полка — `update_record` на `stock.picking.type` → `default_location_dest_id` (только если пользователь явно указал полку и согласен на настройку типа операции).

---

## Шаг 4 — Товары (для каждой строки счёта)

### Поиск

1. По артикулу: `default_code` = артикул из счёта.
2. По имени: `name ilike` ключевые слова (Ду, размер, бренд).

### Создание (если не найден)

```
create_record(
  model="product.template",
  values={
    "name": "<наименование>",
    "default_code": "<артикул>",       # если есть
    "categ_id": <категория>,
    "uom_id": 31,                      # шт.; для труб пог. м — uom_id метра
    "purchase_ok": true,
    "sale_ok": false,
    "is_storable": true,               # складской учёт — обязательно для материалов
    "standard_price": <цена>,
    "list_price": <цена>
  }
)
```

### Категории (ориентир)

| Тип товара | categ_id (имя) |
|------------|----------------|
| Крепёж, расходники | Расходники (12) |
| ЛКМ, грунтовка | ЛКП (5) |
| Трубы ПП, фитинги | Фасонные части (11) |
| Металлопрокат | Трубы (14) |
| Оборудование, счётчики | Оборудование (7) |
| Арматура | Арматура трубопроводная (13) |

### Поставщик на карточке

```
create_record(
  model="product.supplierinfo",
  values={
    "partner_id": <id поставщика>,
    "product_tmpl_id": <id>,
    "price": <цена>,
    "product_code": "<артикул>"
  }
)
```

## Шаг 5 — Скидка по строке

Если в счёте есть колонки «Сумма без скидки» и «Сумма»:

```
discount = round((1 - sum_after / (qty * price_unit)) * 100, 2)
```

- **ОАО УПТК «Амурстрой»** — часто 5% на все строки; сверяй с итогом.
- **ООО «ТД Центр Снабжения»** — обычно без скидки, цена × кол-во = сумма.
- При расхождении итога — **остановись и уточни у пользователя**. Не подбирай скидки/цены эвристически, если OCR уже пометил `needs_review`.

---

## Шаг 6 — Создать purchase.order

```
create_record(
  model="purchase.order",
  values={
    "partner_id": <id>,
    "picking_type_id": <in_type_id склада>,
    "partner_ref": "<номер счёта>",
    "origin": "Счёт <номер>",
    "date_order": "<дата счёта> 12:00:00",
    "order_line": [
      [0, 0, {
        "product_id": <product.product id>,
        "product_qty": <qty>,
        "product_uom_id": 31,
        "price_unit": <price>,
        "discount": <discount>
      }],
      ...
    ]
  }
)
```

`product_id` — id варианта (`product.product`), обычно совпадает с `product.template` для простых товаров.

---

## Шаг 7 — Валидация

- Для обычных счетов: `amount_total` PO ≈ «Итого» счёта.
- Для ОАО УПТК «Амурстрой» (договор-счёт): `Σ price_subtotal` строк ≈ `totals.subtotal_wo_vat` / строке «на сумму … руб», а `amount_total` может отличаться от OCR-строки «Итого» с НДС.
- Количество строк PO = количеству позиций в таблице (без рекламных блоков).
- `picking_type_id` указывает на нужный склад.

При ошибке, `sum_mismatch`, `items_empty` или `needs_review: true` — не создавать и не исправлять PO молча; покажи расхождение и запроси подтверждение/уточнение.

```
- Ссылка: https://...
```

Для пакета счетов — отдельный блок на каждый файл.

## Типичные форматы счетов

### ОАО УПТК «Амурстрой» (скан)
Договор-Счет № П00001XXXX. OCR → `amurstroy-invoice-parsing`; при `needs_review` создание PO блокируется до подтверждения пользователя.

### 1С / ИП (текстовый PDF)
«Счет на оплату № НФ-684». Таблица: Товар | Кол-во | Ед. | Цена | Сумма.

### ООО «ТД Центр Снабжения» (текстовый PDF)
«Счет на оплату № УТБФ000XXXX». Колонка **Артикул** — обязательно в `default_code`.
