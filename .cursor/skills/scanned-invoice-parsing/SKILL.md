# Распознавание сканированных счетов (OCR)

## Когда применять

1. Пользователь просит **распарсить / посмотреть / разобрать** счёт, накладную, договор-счёт.
2. PDF в `docs/invoices/` или загруженный пользователем.
3. `pdfplumber` возвращает пустой текст (`chars == 0`, `images >= 1`).

**Не заносить данные в Odoo** без явной команды пользователя (см. правило `agent-intent-odoo-mcp`).

---

## Шаг 1 — Определить тип PDF

```python
import pdfplumber
with pdfplumber.open(path) as pdf:
    page = pdf.pages[0]
    has_text = len(page.chars) > 0
```

| Результат | Действие |
|-----------|----------|
| `has_text == True` | Модуль `ai_assistant` → `extract_invoice(bytes)` или regex из `extractor.py` |
| `has_text == False` | OCR (шаг 2) |

---

## Шаг 2 — OCR (сканы)

Запусти скрипт проекта (предпочтительно):

```bash
python3 .cursor/skills/scanned-invoice-parsing/scripts/ocr_parse.py "docs/invoices/<файл>.pdf"
```

Скрипт: рендер 400 dpi → контраст → Tesseract `rus+eng` → кроп таблицы → JSON.

**Зависимости:** `pdfplumber`, `pytesseract`, `Pillow`; системный `tesseract` с `rus`.

Если скрипт недоступен — тот же pipeline в одноразовом Python (см. `scripts/ocr_parse.py`).

---

## Шаг 3 — Постобработка OCR

После OCR примени словарь исправлений из [ocr-corrections.md](ocr-corrections.md).

### Приоритет источников

1. **ИНН** — эталон для идентификации контрагента (10/12 цифр).
2. **Сумма строк = Итого** — проверка таблицы.
3. **Уточнения пользователя** — перекрывают OCR (пример: «DIN 934», не ГОСТ).
4. **Контекст номенклатуры** — крепёж: М6, DIN, ГОСТ, шт/кг.

### Типичный формат ОАО УПТК «Амурстрой»

**Полный workflow** — скилл **amurstroy-invoice-parsing** (`.cursor/skills/amurstroy-invoice-parsing/SKILL.md`).

Кратко:
- Заголовок: `Договор-Счет № <номер> от ДД.ММ.ГГ`
- Блок платёжки сверху: ИНН/КПП, р/с, БИК, банк
- Метки **«Поставщик:»** / **«Покупатель:»** — реквизиты часто на соседних строках (OCR путает порядок)
- Покупатель часто: **ООО «Теплосервис-Комплект»**, ИНН `2801131520`
- Таблица: `Товар | Кол-во | Ед. | Цена | Скидка | Сумма`
- Рекламные блоки («В продаже имеются…», цена без строки в таблице) — **не включать** в позиции

### Идентификация поставщика по ИНН

| ИНН | Организация |
|-----|-------------|
| `2801019127` | ОАО УПТК «Амурстрой» |

## Шаг 4 — Структура ответа пользователю

Покажи результат в фиксированном виде:

### Документ
- Тип, номер, дата, итого, НДС, кол-во позиций

### Поставщик
- Название, ИНН, КПП, адрес, телефон, email
- Банк (справочно, **не для Odoo** `res.partner`)

### Покупатель
- Название, ИНН, КПП, адрес

### Позиции

| № | Наименование | Кол-во | Ед. | Цена | Сумма |

### Примечания по качеству
- Указать, что PDF — скан
- Перечислить поля с низкой уверенностью OCR
- Отметить проверку: `Σ позиций == Итого`

---

## Шаг 5 — Валидация

```
✓ ИНН поставщика: 10 цифр (юрлицо) или 12 (ИП)
✓ Сумма позиций ≈ Итого (допуск 0.01 ₽)
✓ НДС ≤ Итого
✓ Рекламные строки не в таблице
```

При расхождении — сообщи пользователю, не додумывай цифры.

---

## Шаг 6 — Связь с Odoo

1. Реквизиты поставщика → скилл `odoo-supplier-from-invoice`
2. Товары / закупку — отдельная явная команда
