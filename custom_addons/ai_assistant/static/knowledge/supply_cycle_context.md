# Supply cycle actions context

**Ключевые слова**: снабжение, закупка, требование, приход, ОбМ, object.request, purchase.order, stock.picking, УТ-1132

## Роли

- Прораб: создает `object.request`, указывает объект/проект, срок и строки потребности.
- Снабженец: разбирает OR, выбирает "с базы" или "закупка", готовит PO/internal picking, завершает Confirm/Validate в UI.
- Кладовщик или прораб объекта: принимает факт и сверяет метраж.
- AI: ищет товары, остатки, склады и готовит только черновики OR/PO/picking после UI-подтверждения.
- Бухгалтерия: счет, оплата, НДС и банк ведутся в 1С, не в Odoo.

## Склады объектов и picking type

Объектные склады имеют код `ОбМ-N`. Для PO нужен `stock.warehouse.in_type_id` склада объекта, для внутреннего перемещения - `stock.warehouse.int_type_id`, назначение - `stock.warehouse.lot_stock_id`.
Tool `find_warehouse` принимает `query`: можно передать код склада (`ОбМ-4`, `ОбМ-`) или часть названия/адреса (`Хмельницкого`, `Ломоносова`).

| Объект | Код склада | PO incoming picking type | Internal picking type |
|---|---|---|---|
| Амурком, Островского 234 | ОбМ-1 | `ОбМ-1: Поступления` (`in_type_id`) | `ОбМ-1: Внутренние переводы` (`int_type_id`) |
| Ломоносова 164 | ОбМ-2 | `ОбМ-2: Поступления` (`in_type_id`) | `ОбМ-2: Внутренние переводы` (`int_type_id`) |
| Ленина 231 | ОбМ-3 | `ОбМ-3: Поступления` (`in_type_id`) | `ОбМ-3: Внутренние переводы` (`int_type_id`) |
| Б. Хмельницкого, 112 | ОбМ-4 | `ОбМ-4: Поступления` (`in_type_id`) | `ОбМ-4: Внутренние переводы` (`int_type_id`) |

Нельзя создавать закупку на офисный/дефолтный склад, если потребность относится к `ОбМ-*`.

## Количество труб

До закрытия TD-002 AI только подсказывает пересчет, но записывает в строки уже согласованные метры:

- штуки хлыстов: `шт * длина_хлыста`;
- килограммы: `кг / кг_на_метр`;
- тонны: `т * 1000 / кг_на_метр`.

Пример УТ-1132: 1.5*12 + 15*12 + 13*6 + 51*6 + 30*6 + 56*6 = 1098 м.

## Denylist процесса

AI не вызывает `button_confirm`, `button_validate`, `action_done`, `action_post`; не пишет `state` напрямую; не использует `stock.quant.write/create/unlink` и inventory adjustment; не создает `account.move` vendor bill или платежи; не работает с `res.users`, `res.groups`, `ir.model.*`, `ir.ui.*`; не удаляет проведенные документы.

Остатки появляются только после штатного Validate в UI или после закрытия TD-003. Прямой перевод picking в `done` через API дает документ без quants.

## Правильный план PO

Для запроса "создай PO по счету УТ-1132 на ОбМ-4":

1. Найти OR и объект: `origin = OR/...`.
2. Найти склад `ОбМ-4`, взять `in_type_id`.
3. Найти поставщика по ИНН/имени, проверить `supplier_rank > 0`.
4. Найти товары, проверить `is_storable = true`.
5. Показать план и дождаться кнопки подтверждения.
6. Создать `purchase.order` в `draft`: `partner_id`, `picking_type_id = ОбМ-4.in_type_id`, `origin`, `partner_ref = УТ-1132`.
7. Добавить строки в метрах; для труб с UoM не метр - вернуть предупреждение.
8. Записать note в chatter: создано AI-ассистентом, пользователь, источник и краткая сводка.
